# 四、第 3 阶段：I/O 多路转接专项突破

你现在说多路转接没掌握好，核心是没有把这条线串起来：

```text

阻塞 I/O
非阻塞 I/O
select
poll
epoll
Reactor
```

你要按这个顺序学。

------

## 1. 先理解阻塞和非阻塞

阻塞 I/O：

```cpp
read(fd, buf, sizeof(buf));
```

如果没有数据，程序会卡住。

非阻塞 I/O：

```cpp
fcntl(fd, F_SETFL, O_NONBLOCK);
```

如果没有数据，`read` 会返回 `-1`，并且 `errno` 是：

```cpp
EAGAIN
EWOULDBLOCK
```

你必须理解：

```text
非阻塞不是不读数据
而是没有数据时不傻等
```

------

## 2. 再理解 select

`select` 的作用是：

```text
帮你同时监视多个 fd
看哪些 fd 可读、可写、异常
```

基本流程：

```cpp
fd_set rfds;
FD_ZERO(&rfds);
FD_SET(listenfd, &rfds);

select(maxfd + 1, &rfds, nullptr, nullptr, nullptr);

if (FD_ISSET(listenfd, &rfds))
{
    accept(listenfd, ...);
}
```

你要知道 `select` 的缺点：

```text
fd_set 有大小限制
每次都要重新设置 fd_set
每次都要从 0 遍历到 maxfd
用户态和内核态频繁拷贝 fd 集合
```

------

## 3. 再理解 poll

`poll` 相比 `select` 的变化：

```text
不用 fd_set
使用 pollfd 数组
没有固定的 1024 限制
```

核心结构：

```cpp
struct pollfd
{
    int fd;
    short events;
    short revents;
};
```

但是它仍然有问题：

```text
每次调用都要把数组传给内核
返回后仍然要遍历整个数组
连接很多时效率不高
```

------

## 4. 最后理解 epoll

`epoll` 的核心优势是：

```text
把关心的 fd 提前注册到内核
有事件发生时，内核只返回就绪的 fd
不用每次遍历所有 fd
```

核心接口：

```cpp
epoll_create
epoll_ctl
epoll_wait
```

基本流程：

```cpp
int epfd = epoll_create(128);

struct epoll_event ev;
ev.events = EPOLLIN;
ev.data.fd = listenfd;

epoll_ctl(epfd, EPOLL_CTL_ADD, listenfd, &ev);

while (true)
{
    struct epoll_event events[1024];
    int n = epoll_wait(epfd, events, 1024, -1);

    for (int i = 0; i < n; ++i)
    {
        int fd = events[i].data.fd;

        if (fd == listenfd)
        {
            accept(listenfd, ...);
        }
        else
        {
            read(fd, ...);
        }
    }
}
```

你要重点理解：

```text
epoll_ctl 是注册事件
epoll_wait 是等待事件
epoll_event.data.fd 用来知道哪个 fd 就绪
```
